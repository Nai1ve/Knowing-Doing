# Information Architecture: 知行桌面端

## Site Map

- 学习总览 `/`
  - 当前计划
  - 今日学习
  - 待复习与近期变化
- 建立计划 `/plans/new`
  - 目标与时间
  - 材料输入 `/plans/new/materials`
  - 画像确认 `/plans/new/profile`
  - 动态诊断 `/plans/new/diagnosis`
  - 计划确认 `/plans/new/preview`
- 我的计划 `/plans`
  - 计划概览 `/plans/:planId`
  - 学习路线 `/plans/:planId/route`
  - 学习单元 `/plans/:planId/units/:unitId`
  - 周复盘 `/plans/:planId/reviews/:reviewId`
  - 来源库 `/plans/:planId/sources`
  - 任务分支 `/plans/:planId/branches/:branchId`（P1）
- 学习档案 `/profile`
  - 画像与材料 `/profile/evidence`
  - 掌握状态 `/profile/mastery`
  - 学习偏好 `/profile/preferences`
- 设置 `/settings`
  - 知乎与模型连接 `/settings/connections`
  - 数据与隐私 `/settings/data`

## Navigation Model

- **Primary navigation**: 学习总览、我的计划、学习档案，最多三个主入口。
- **Plan page navigation**: 进入一份计划后，使用四个相互独立的页面：总览、完整路线、当前学习、周复盘。页面之间共享计划上下文，但不把正文混排在首页。
- **Page-local navigation**: 右侧使用 “On this page” 目录，只列当前页面的章节，不承担全局导航职责。
- **Utility navigation**: 新建计划、连接状态、设置和账户在窗口顶部右侧。
- **Desktop behavior**: 左侧是稳定的章节导航，中间是单页正文，右侧是当前页目录和少量上下文信息。
- **Web-first behavior**: 桌面优先 Web 保持应用壳体验；本地终端、文件和 Kubernetes 上下文通过“手动粘贴”或用户授权的 CLI 连接器接入。
- **Mobile behavior**: 第一版仅支持查看计划、复盘和提醒；材料解析、计划编辑和完整练习保留在桌面端。

## Content Hierarchy

### 学习总览

1. 当前学习目标和距离下一里程碑的状态；
2. 当前状况和当前所在节点；
3. 整体学习路线的摘要，不展示所有学习正文；
4. 今日学习入口和近期变化。

### 完整路线

1. 最终能力目标和整体路线范围；
2. 所有里程碑和每个里程碑的完成定义；
3. 当前节点在完整路线中的位置；
4. 各阶段学习单元的状态和进入入口。

### 当前学习

1. 当前学习单元的目标和所属里程碑；
2. 理解、构建、运行、证明、继续的学习循环；
3. 外部编辑器、终端和运行数据入口，知行不嵌入这些工具；
4. 知行 AI 的当前追问与可选追问方向；
5. 当前问题的 AI 对话流和继续追问入口；
6. 按当前问题整理的知乎知识摘要与来源；
7. 已固定的常用判断、AI 回答或知乎摘要；
8. 检查点、学习证据和下一步动作。
9. 上下文接入：粘贴 YAML、终端输出或错误日志，或启动 CLI 自动抓取。

### 学习笔记

1. **实践记录**：按参考、问题、错误、观察四类展示自动采集的素材，并保留知乎、Tutor Agent、外部工具、检查点等来源。
2. **整理大纲**：模型根据素材生成候选大纲；用户可编辑、调序、删除和补充，确认事实与文章意图。
3. **成文发布**：模型或用户完成文章正文；预览同步更新，发布前检查来源、隐私、敏感信息和可复现步骤。
4. **发布状态**：草稿、待人工确认、已授权发布和已发布必须是不同状态，不能把“生成文章”视为“发布成功”。

### 建立计划

1. 用户目标、时间和想达到的能力；
2. 系统从材料中提取的可确认画像；
3. 动态诊断问题与结果；
4. 生成的数周路线及每项推断的依据。

### 周复盘

1. 计划与实际的差异；
2. 掌握状态和检查点结果；
3. 调整建议及其依据；
4. 用户确认后的下一周安排。

## User Flows

### 系统学习一项技术

1. 用户在学习总览点击新建计划。
2. 输入目标技术、目标能力、完成日期和每周可用时间。
3. 选择是否补充自述、简历或知乎收藏等材料。
4. 系统展示画像推断；用户确认、修改或删除。
5. 系统进行动态追问和短题诊断。
6. 系统生成四周学习路线；用户调整节奏或已掌握内容。
7. 用户确认计划，进入学习总览和今日学习单元。

### 完成一个学习单元

1. 用户从总览进入今日学习。
2. 看到单元目标、预计时间和所属里程碑。
3. 查看 AI 追问、知乎知识摘要和当前节点的原理说明。
4. 从工作台打开外部编辑器、终端或运行数据工具完成实践。
5. 用户选择手动粘贴上下文，或启动已授权的 CLI 连接器自动抓取。
6. 与知行 AI 讨论当前问题，必要时把回答或来源固定下来。
7. 回到知行完成预测、解释或检查点，并记录证据。
8. 系统自动追加参考、问题、错误、观察和证据到实践记录。
9. 用户进入学习笔记，确认 AI 生成的大纲，选择由模型或自己完成文章。
10. 用户检查文章内容并明确授权后，系统才调用知乎发布能力。
11. 系统展示掌握判断和证据，更新路线和下一步。

### 周复盘并调整计划

1. 系统在里程碑结束或每周结束时提醒复盘。
2. 用户看到计划/实际时间、单元完成、薄弱概念和提示依赖。
3. 系统说明建议调整的原因和影响。
4. 用户接受、修改或拒绝调整。
5. 系统局部更新后续路线，已完成内容保持不变。

### 真实任务打断学习（P1）

1. 用户在当前计划中创建一个任务分支，或从任务入口提交问题。
2. 系统标记相关概念和当前里程碑。
3. 用户完成最小必要的学习与实践。
4. 系统记录任务结果，并给出回归主计划或调整时间的建议。

## Naming Conventions

| Concept | Label in UI | Notes |
| --- | --- | --- |
| Learning plan | 学习计划 | 围绕一项技术和明确目标的数周路线 |
| Milestone | 里程碑 | 可验证的阶段能力目标 |
| Learning unit | 学习单元 | 15 至 60 分钟的完整学习与练习动作 |
| Learner profile | 学习档案 | 用户确认后的背景、目标和偏好 |
| Profile evidence | 画像依据 | 自述、简历、收藏、问答和练习结果 |
| Concept state | 掌握状态 | 已掌握、练习中、待补充、待复习 |
| Checkpoint | 检查点 | 用于判断理解和迁移的作答或实践 |
| Plan adjustment | 计划调整 | 系统提出且用户可确认的局部重排 |
| Task branch | 任务分支 | 从主计划临时展开的真实任务处理路径 |
| Source | 来源 | 知乎内容在当前学习单元中的可追溯引用 |

## Component Reuse Map

| Component | Used on | Behavior differences |
| --- | --- | --- |
| App shell | 全部页面 | 学习单元隐藏次要导航以减少干扰 |
| Plan route | 总览、计划概览、复盘 | 总览显示近期节点，概览显示完整路线 |
| Milestone summary | 总览、路线、复盘 | 总览突出当前项，复盘显示前后变化 |
| Profile evidence item | 建立计划、学习档案 | 建立计划需要确认，档案页可重新编辑 |
| Source drawer | 学习单元、来源库、任务分支 | 学习单元按当前概念过滤 |
| Learning workbench | 当前学习、任务分支 | 提供外部工具入口，右侧聚合 AI 追问与知乎摘要 |
| AI conversation | 当前学习、任务分支 | 按当前节点追加对话，支持从消息创建固定参考 |
| Pinned reference | 当前学习、任务分支、复盘 | 当前工作台即时显示，允许取消固定；不改变主路线顺序 |
| Practice journal | 当前学习、学习笔记、任务分支 | 自动记录实践素材，按来源和类型筛选；保留原始事实 |
| Article workflow | 学习笔记 | 素材生成大纲，人工确认后进入 AI/人工成文和知乎发布 |
| Checkpoint | 学习单元、复盘 | 学习单元作答，复盘展示结果与趋势 |
| Adjustment notice | 总览、路线、复盘 | 总览只提示待确认，路线显示影响范围 |

## Content Growth Plan

- 用户可拥有多份学习计划，默认突出当前活跃计划，历史计划归档；
- 学习单元、来源、检查点和复盘记录随时间增长，按计划与里程碑筛选；
- 知识领域可扩展，但计划、里程碑、单元和检查点的结构保持稳定；
- 收藏、简历和历史学习记录只按需读取，不在总览一次性加载；
- 任务分支在 P1 增长后仍归属于一份学习计划，避免成为另一个独立任务系统。

## URL Strategy

- Pattern: `/plans/:planId/:subview` and `/profile/:subview`
- Dynamic segments: `planId`、`unitId`、`reviewId`、`branchId`
- Query parameters: `milestone`、`source`、`status`、`page`
- Desktop shell supports deep links such as `/plans/k8s-2026/units/k8s-workloads?source=zhihu`.

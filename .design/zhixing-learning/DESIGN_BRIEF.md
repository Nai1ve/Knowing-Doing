# Design Brief: 知行桌面端个性化学习系统

## Problem

开发者想系统学习一项技术，却要在收藏夹、零散文章、课程、AI 对话和真实任务之间自行安排顺序。他们不知道自己的起点是否判断准确，也无法看清数周学习之后是否真正朝目标前进。真实任务和突发问题经常打断计划，但现有工具不会把这些经历重新编排为更合适的学习路径。

## Solution

知行从用户目标、授权材料和动态追问建立可修正的学习画像，生成带里程碑的数周学习计划。用户每天在同一空间中学习一个明确的单元、阅读被编排的知乎内容、完成主动练习、记录掌握状态；系统在每周复盘和真实任务发生时解释性地调整计划。

## MVP Scope

黑客松版本不实现上述长期学习计划。它先证明最小但完整的价值：用户在一个 MySQL 慢查询场景中，沿“症状 -> 假设 -> 证据 -> 修复 -> 对比 -> 文章预览”完成一次工程判断。案例阶段、必需证据和提示阶梯由确定性代码控制；知乎内容是有角色、有来源的参考，模型只在当前阶段提问、解释和整理。

## Experience Principles

1. **诊断先于推荐** -- 首先让用户看见系统如何理解自己，并可修正所有推断，再展示学习计划。
2. **里程碑先于内容堆积** -- 每个屏幕优先回答“我正在朝哪个能力目标前进、现在该做什么”。
3. **调整可见且可控** -- 计划变化必须显示触发原因、影响范围和保留的进度，用户始终可以确认或撤回。

## Aesthetic Direction

- **Philosophy**: Editorial technical learning navigator。它像一套可以持续阅读和实践的技术教材，同时保留桌面软件的稳定导航。
- **Tone**: 平静、专注、有方向感；帮助用户建立掌控感，不制造进度焦虑。
- **Reference points**: AI Engineering From Scratch 的课程阅读结构、技术文档的章节层级、桌面编辑器的持久导航。
- **Anti-references**: 密集数据仪表盘、单线程聊天机器人、游戏化打卡界面、把所有页面内容塞在首页的超级工作台。

## Visual Direction

- 它首先是一款桌面优先的 Web 学习软件：不模拟原生窗口标题栏，保留稳定侧栏、正文学习区和当前页上下文，但 MVP 不要求原生安装包。
- 采用“深色应用 Chrome + 纸张感学习画布”的主题：深石墨表达系统边界，暖灰白承载长时间阅读，钴蓝表达章节、规则线和当前节点，橙色只强调待确认的计划变化。
- 正文使用高可读性的系统中文无衬线字体，章节标题可使用有编辑感的衬线字体，代码、命令和概念标签使用等宽字体；小标签使用英文/数字和紧凑字距，建立技术教材气质。
- 页面采用“左侧导航 + 中央单页内容 + 右侧上下文辅助”结构。MVP 的总览、场景训练和实践笔记分别承担单一任务，不在首页混合完整正文；场景训练是受限的实践工作台，承载外部工具入口、AI 追问和知乎知识上下文。
- MVP 的记忆点是“可回溯的工程判断”：用户从症状进入证据链，最后能看到每个结论由什么实验和来源支撑。长期版本再扩展为可回溯的学习章节。

## Existing Patterns

当前已有 Vue 3 + TypeScript + Vite + Pinia + Vue Router 前端骨架。App shell、导航、页面标题、工作台、Tutor Agent、实践记录、笔记编辑器和 OAuth 设置页均已存在，但当前内容仍是 K8s Mock，需要在首个场景纵切中替换为 MySQL 案例数据，而不是重新搭建一套页面。

- Typography: 系统中文无衬线 + 等宽代码字体
- Colors: 深石墨 Chrome、暖灰白画布、钴蓝规则线、浅紫内容面、学习橙、低饱和绿、错误红
- Spacing: 4px 基础单位，8px 和 16px 为主要间距节奏
- Components: 应用框架、章节导航、页面目录、总目标面板、里程碑路线、学习单元、来源区块、检查点、计划调整说明、画像确认项

## Key Interactions

- 首次进入时，用户先输入想学习的技术和目标，可选添加收藏、简历和自述；系统先显示“我目前如何理解你”，不直接跳到课程表。
- 动态追问每次只提出当前最能缩小计划不确定性的问题，并在用户回答后展示它如何影响计划。
- 计划生成后，用户可拖动完成日期、调整每周时间或标记已掌握内容；路线局部重排并保留已完成记录。
- 学习总览只强调当前里程碑和“今天下一步”，完整计划地图可在需要时展开，避免首次进入被数周内容淹没。
- 学习单元中，知乎内容以“为什么现在读它”和“它支撑哪个概念”呈现；AI 负责追问和拆解，外部编辑器/终端负责真实执行，知行只记录上下文与证据。
- AI 对话按当前节点持续追加，用户可以把一条常用判断、AI 回答或知乎摘要固定到工作台，作为本次实践的即时参考。
- 检查点结束时，系统展示掌握判断和证据；用户可标记“我不同意”，触发补充追问或替代练习。
- 实践过程中，系统默认记录参考、问题、错误、运行观察和用户证据；学习笔记页按“实践记录 → 整理大纲 → 成文发布”分阶段展示。
- 当前学习工作台提供“粘贴上下文”和“CLI 自动抓取”两种接入方式；Web 页面不直接执行本地命令，CLI 连接器通过用户授权完成采集。
- AI 只生成候选大纲和文章草稿，用户先确认事实与结构，再决定由模型或自己完成文章；知乎发布前保留人工检查和授权动作。
- 发生真实任务时，系统创建临时分支，标记它影响的概念与计划时间；完成后提供“回归主计划”的明确动作。

## Responsive Behavior

第一版为桌面优先 Web 系统，基准窗口为 1440x900，最低支持 1024px 宽度。页面包含应用侧栏、主学习区和右侧上下文栏，不再套用原生窗口标题栏。

- 左侧主导航在窄窗口收为图标栏；
- 计划路线在中等宽度下保持纵向可读，来源和学习档案转为右侧抽屉；
- 学习单元保持单列阅读与练习区，避免代码和正文被压缩；
- 移动端只支持计划查看、复盘和提醒，不提供完整的计划编辑与实践流程。

## Accessibility Requirements

- 图标按钮提供可读标签、悬停提示和键盘操作；
- 路线、进度和掌握状态不能只依赖颜色，必须有文本或图标；
- 路线、来源抽屉、练习和调整确认具有清晰的焦点顺序；
- 正文、状态与互动控件满足 WCAG AA 对比度；
- 长来源、简历解析结果和练习反馈可以被键盘滚动、复制和屏幕阅读器理解；
- 动画尊重 reduced-motion 设置，路线状态变化不依赖自动播放。

## Out of Scope

- 移动端完整学习和计划编辑体验；
- 全部技术领域的完整内容覆盖；
- 面向生产集群的通用运维控制台；
- 多案例、任务分支和数周计划的完整体验；
- 社区内容发布、课程交易和社交排行。

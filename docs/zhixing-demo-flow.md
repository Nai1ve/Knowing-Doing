# 知行黑客松 Demo 流程与分支覆盖

版本：v0.1

## 1. Demo 目标

评委最终应看到的不是“AI 给出一个索引答案”，而是一条可以回溯的工程判断链：

```text
工程症状
  -> 用户假设
  -> 知乎参考与 Tutor 追问
  -> 用户提交 EXPLAIN 证据
  -> 记录一次失败尝试
  -> 修复并比较证据
  -> 问题已解决
  -> 按需生成可编辑的知乎文章预览
```

主 Demo 只走一个 MySQL 案例，不展示学习计划、K8s、Kafka、Redis、真实发布或账号授权。异常分支要体现系统有边界和可恢复性，不把错误页面变成新的产品主线。

## 2. 主路径：三分钟黄金演示

主路径使用案例 `mysql-order-list-index-001`，演示者只需要准备一个用户假设、三份 EXPLAIN 和一份前后基准结果。每一步都要让评委看到“用户做了什么”和“系统凭什么允许下一步”。

| 时间 | 状态 | 演示者动作 | 页面必须出现 | 旁白重点 |
| ---: | --- | --- | --- | --- |
| 0:00-0:20 | 进入 `observe` | 从总览点击“继续训练” | 症状、约束、表结构、现有索引；不显示问题 SQL | 这是从有限现场信息开始的工程诊断 |
| 0:20-0:35 | `observe` | 请求慢日志并选中订单列表 SQL | 脱敏慢日志、只读 SQL 参考、空白执行编辑器、Tutor 主动提出下一步验证问题 | AI 不替用户跳过取证步骤，也不暴露真实业务参数 |
| 0:35-0:50 | `hypothesize` | 提出可验证假设 | 用户假设事件；Tutor 引导说明验证方式 | AI 不替用户直接下结论 |
| 0:50-1:10 | `inspect` | 运行初始 EXPLAIN | 原文、`type`、`key`、`rows`、`Extra` 证据卡 | 知乎内容只作为当前阶段的参考，结论来自证据 |
| 1:10-1:25 | `inspect` | 说明观察到的字段或疑点 | Tutor 仅围绕用户观察继续追问 | 先由用户阅读证据，再获得解读 |
| 1:25-1:45 | `attempt` | 提交一次不充分的修改 | 失败尝试、第二份 EXPLAIN、局限说明 | 系统记录失败，而不是只展示成功答案 |
| 1:45-2:20 | `verify` | 改写时间范围并加入联合索引，运行最终证据 | 前后 EXPLAIN、基准、结果集一致性、残余风险 | 判断性能改善不能只看 `type` 一个字段 |
| 2:20-2:30 | `resolved` | 查看验证结果 | 根因、修复、前后证据、残余风险、“问题已解决”状态与笔记已生成入口 | 证据满足时，实践任务在这里完成；笔记不阻塞完成，也不自动跳转 |
| 2:30-2:40 | `reflect` | 按需编辑笔记大纲 | 可编辑的结论与复盘材料 | 复盘用于沉淀，不阻塞完成状态 |
| 2:40-3:00 | 文章预览 | 点击“整理成文章” | 完整可编辑初稿、问题、假设、实验、失败、验证、来源和人工检查状态 | 从实践证据自然生成知乎创作素材，仍待人工审核 |

### 主路径的固定输入

- 症状：订单列表在演示环境中出现慢查询；不得标成生产事故。
- 脱敏慢日志：固定仅含订单列表目标 SQL 与一条无关后台统计语句；目标 SQL 的 `DATE(created_at)` 条件在用户选中后才进入可运行演示副本。
- 初始 EXPLAIN：展示当前访问路径和扫描成本，原文必须可展开。
- 演示参考路径中的不充分尝试：创建 `(user_id, status, created_at)` 联合索引，但保留 `DATE(created_at)` 条件；必须保留实际 EXPLAIN、基准与“局部改善仍不足”的证据，不能先验地称为完全失败。真实用户可走其他尝试路径。
- 最终尝试：左闭右开时间范围 + `(user_id, status, created_at)` 候选索引。
- 最终判断：结果集语义一致、扫描成本下降、基准有可比环境；没有达到条件时停留在“证据不足”。

## 3. 状态转移与分支规则

### 状态图

```text
idle
  -> observe
  -> hypothesize
  -> inspect
  -> attempt
  -> verify
  -> resolved
      -> reflect
      -> article_preview
```

状态由代码维护。Tutor、知乎检索和文章模型都只能产生事件或建议，不能直接把状态改成下一阶段。每次转移都要追加事件，不能通过解析聊天文本推断用户已经完成了证据提交。

### 状态转移表

| 当前状态 | 最小退出条件 | 可进入下一状态 | 不满足时的行为 |
| --- | --- | --- | --- |
| `observe` | 用户写出初始现象或判断，并承认需要执行计划验证 | `hypothesize` | 提示区分“慢”与“未走索引” |
| `hypothesize` | 有一条可被 EXPLAIN 支持或证伪的假设和验证命令 | `inspect` | 允许修改假设，不生成最终答案 |
| `inspect` | 有完整 EXPLAIN 原文、至少两个核心字段，以及用户对字段的观察 | `attempt` | 保留原文，引导用户说明观察；不自动解释或推进 |
| `attempt` | 有一次 SQL/DDL 修改和第二份证据，并解释局限 | `verify` | 标记失败尝试，不允许跳到验证完成 |
| `verify` | 有最终 SQL、最终 EXPLAIN、基准和结果集一致性检查 | `resolved` | 显示“证据不足”或“未支持”，允许继续实验 |
| `resolved` | 展示根因、修复与证据链接，并异步生成笔记大纲 | `reflect`、`article_preview` 或结束训练 | 已是完成态；笔记生成失败时使用模板，后续内容不改变完成判定 |
| `reflect` | 用户确认或编辑结论、复现步骤和残余风险 | `article_preview` 或结束训练 | 可生成待人工审核的完整初稿，不能撤销已验证的实践完成态 |

## 4. 分支模拟矩阵

### 必须在 MVP 覆盖的分支

| 分支 ID | 触发方式 | 预期系统行为 | 是否阻断主流程 | Demo 处理 |
| --- | --- | --- | --- | --- |
| `B01-replay` | 选择回放模式 | 加载固定事件和证据，仍按状态顺序播放 | 否 | 现场网络或模型异常时启用 |
| `B02-weak-hypothesis` | 输入“加索引就行” | Tutor 追问验证方法，状态停在 `hypothesize` | 否 | 可作为主路径的第一处互动 |
| `B03-empty-input` | 空提交 SQL/EXPLAIN | 显示字段错误，不追加伪证据 | 否 | 不在 3 分钟主线展开 |
| `B04-valid-explain` | 粘贴可解析 EXPLAIN | 保存原文并生成结构化证据卡，先要求用户观察 | 否 | 主路径必须展示 |
| `B04a-log-selection-mismatch` | 选中无关慢日志语句 | Tutor 要求解释该语句与症状的关联，不直接纠正；连续两次后定向提示 | 否 | 不在黄金路径展开 |
| `B05-unknown-explain` | 粘贴 JSON/TREE 或未知格式 | 保存原文，字段标为未知，要求用户确认 | 否 | 展示“保留事实，不乱猜” |
| `B06-failed-attempt` | 修改后扫描成本未改善 | 记录失败尝试和原因，允许继续修改 | 否 | 主路径必须展示 |
| `B07-semantic-drift` | 删除筛选条件或缩小时间范围 | 标记结果语义变化，禁止进入验证通过 | 是当前结论，不阻断重试 |
| `B08-insufficient-proof` | 最终只有 EXPLAIN，没有基准或结果集校验 | 显示“倾向支持/证据不足”，不能写“优化完成” | 否 | 作为失败回放数据 |
| `B09-verified` | 前后证据满足规则 | 进入 `resolved`，允许结束训练或生成沉淀材料 | 否 | 主路径必须展示 |
| `B10-article-draft` | 事件链完整，点击整理文章 | 生成带证据和来源引用的完整可编辑初稿，标记待人工审核 | 否 | 主路径必须展示 |

### 外部依赖与环境分支

| 分支 ID | 触发方式 | 预期系统行为 | 兜底 |
| --- | --- | --- | --- |
| `B11-tutor-timeout` | Tutor 请求超时或返回非法结构 | 保留用户问题，显示状态机提示和手动提示按钮 | 使用预置 Tutor 回复，不改变状态 |
| `B12-zhihu-rate-limit` | 搜索返回限流 | 显示“知乎来源暂不可用”，不伪造来源 | 使用已核验的固定来源卡，并标记为预置 |
| `B13-zhihu-empty` | 搜索无结果 | 显示无匹配和改写建议 | 不阻断 EXPLAIN 实验 |
| `B14-lab-unavailable` | Docker/MySQL 未启动 | 显示启动检查和复制命令 | 切换到固定证据回放 |
| `B15a-note-outline-failure` | 笔记模型失败 | 保留完成态和原始事件，生成可编辑结构化模板 | 不阻断解决结果或文章入口 |
| `B15-article-failure` | 大纲/文章模型失败 | 保留事件时间线，允许人工填写大纲 | 使用结构化模板生成草稿 |
| `B16-browser-refresh` | 用户刷新或重新打开链接 | 恢复案例、状态、事件和固定参考 | 无记录时回到 `observe` |

### 明确延期的分支

以下不是 MVP 的失败态，而是后续阶段新增能力：

- `B17-cli-capture`：用户授权后从本地 CLI 自动读取终端上下文；MVP 只支持手动粘贴。
- `B18-oauth-publish`：真实知乎 OAuth 发布；MVP 只进入高保真草稿预览。
- `B19-multi-case`：Kafka、Redis 和其他案例；不能影响 MySQL 状态机。
- `B20-plan-personalization`：收藏、简历和动态画像驱动的数周学习计划；不进入本次 Demo。

## 5. 现场演示决策树

```text
能正常访问前端？
  ├─ 否 -> 录屏或固定回放
  └─ 是
      能启动 MySQL Lab？
        ├─ 否 -> 回放初始/失败/最终证据
        └─ 是
            Tutor 可用？
              ├─ 否 -> 状态机提示 + 预置 Tutor 回复
              └─ 是 -> 主路径互动
                  知乎检索可用？
                    ├─ 否 -> 固定来源卡并标注预置
                    └─ 是 -> 展示当前阶段来源及使用理由
```

现场只需要在开场前决定一个模式：`live` 或 `replay`。不要在演示中途临时切换数据来源；一旦发现外部依赖不稳定，直接使用回放模式，保持叙事和证据顺序不变。

## 6. 分支覆盖验收

阶段 0 完成前，至少准备并人工走查以下 6 条路径：

1. `live + B02 + B04 + B06 + B09 + B10`：完整黄金路径。
2. `replay + B04 + B06 + B09 + B10`：完全离线路径。
3. `B03`：空输入不产生证据。
4. `B05 + B08`：未知格式或证据不足不误判成功。
5. `B07`：结果语义变化不能被“性能更快”掩盖。
6. `B11 + B12 + B14 + B15a + B15`：外部依赖全部不可用时仍能走到文章预览。

每条路径记录：起始快照、用户输入、状态变化、事件数量、页面截图、失败原因和恢复动作。只有“状态正确”和“页面可讲清楚”同时满足，才算覆盖该分支。
